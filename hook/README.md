# "Jev tap" live hook — design (step 2b, NOT INSTALLED)

> ⚠️ **SUPERSEDED (Sep 17)**: the production integration went through the Codex
> Router's official mechanism instead — a *generic provider* (`--adapter
> openai-responses`) plus `server/jev_server.py`. See `server/INSTALL.md`.
> This folder is kept as a record of the exploration (the LiteLLM-callback
> approach was dropped: `litellm.yaml` is regenerated by the router, so any
> manual edit gets overwritten).

## Principle

A **fail-open, file-only** tap inside the Codex Router's LiteLLM gateway:

1. `async_pre_call_hook` → appends one local JSONL line (no network, no blocking
   work, every exception swallowed → the router NEVER breaks a turn).
2. An out-of-band analyzer (already written: `poc/shadow_replay.py`; a future
   `--source tap` variant) consumes `jev-tap.jsonl`, calls Jev, compares →
   `shadow-log.jsonl`.

**Why file-only:** the Jev call must never sit on a request's critical path.
If Jev is down, if TypeSafe is slow, if the key is missing → the tap still
writes (or not) and Codex keeps going.

## Where it plugs in

- Callback: `~/.codex/codex-router/jev_tap_callback.py` (next to `grok_service_tier_callback.py`)
- Registration: `litellm.yaml` → `callbacks: [..., jev_tap_callback.jev_tap_callback]`

⚠️ **Risks to handle before installing:**
- `litellm.yaml` can be regenerated by a router update → re-apply the line after
  every update (documented here; check with
  `bin/jev-codex-router router status` from the repository root).
- The gateway runs as a service (launchd) → restart the router service after edits.
- The callback must NEVER raise: everything is wrapped in `try/except: pass`.

## Written data (minimal prefix, no secrets)

```json
{"at": "...", "model": "gpt-5.6-astra", "call_type": "acompletion", "stream": true,
 "n_messages": 3, "last_user": "…600 chars max…", "source": "jev-tap"}
```
